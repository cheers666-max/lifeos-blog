我是 Ajing，做大模型训练，主要方向是让模型生成 PPT。

这个博客记录我把一个概念真正学懂的过程。不是笔记摘抄——摘抄留不下什么。这里的每篇都从「为什么要有这个东西」开始，一路推到「这个数字是怎么算出来的」。

写法只有一条规矩：**每个公式后面立刻跟一句「算给你看」和真实数字**。公式不带数值示例，等于没讲。另一个自检标准是能不能讲给八岁小孩听——讲不清就是还没懂，那篇就先不发。

眼下在写的几条主线：偏好优化家族（DPO 怎么把天平指针往好回答那边掰、IPO 怎么给它装个限位器、GRPO 怎么扔掉 critic），Claude Code 的内部架构（用一只西高地小狗讲透 Agent Loop、Tool Use、Permission 和 Hooks），还有我自己那套 Obsidian 加 AI 的学习系统。

Agent 这条线是眼下花时间最多的：从 Agent Loop 往下，工具运行时、上下文与记忆、多 Agent 编排、权限与评估，一个组件一个组件地读源码、自己跑、再写下来。写不出来的地方就是还没懂的地方，所以这些文章同时也是我给自己出的考卷。

LifeOS 这个名字不只是博客名。我在拿一堆 AI Agent 加上 Notion 和 Obsidian，给自己搭一套把学习、项目和日记都跑起来的系统——Notion 管计划和状态，Obsidian 管源码笔记和文章，这个站是它朝外的那一面。

## 这站怎么逛

[心流](/flows/)放没打磨过的东西：日记、读完一本书的当场反应、调通一个东西之后的一句话记录。想清楚了才动笔的长文在[首页](/)那条时间流里，同一主题攒够几篇会收进[系列](/series/)——从第一篇顺着读下去最省力。[推荐](/links/)是我用过读过、觉得值得占用你时间的东西，每条都写了具体理由，不写「很好用」这种废话。

## 为什么叫 LifeOS

一个人怎么学、怎么记、怎么把学到的东西真正用起来，跟一套操作系统没多大区别：有输入，有存储，有调度，也会有跑着跑着就卡死的时候。与其指望自己更自律，不如把系统改好——这个博客本身就是那套系统的一部分。
